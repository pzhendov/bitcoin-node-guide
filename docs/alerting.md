# Telegram and macOS health alerts

The Bitcoin node monitor can deliver state-change alerts through:

- Telegram messages sent from the Ubuntu VM
- macOS Notification Center alerts generated by a user LaunchAgent

Alerts are sent only when the health state changes:

```text
HEALTHY → WARNING
HEALTHY → CRITICAL
WARNING → CRITICAL
WARNING → HEALTHY
CRITICAL → HEALTHY
```

Repeated checks in the same state do not produce duplicate notifications.

No wallet data, private keys, RPC cookies or blockchain details are transmitted. Telegram receives only node health status and relevant warning or critical lines.

## Architecture

```text
Ubuntu systemd timer
        |
        v
bitcoin-node-health-runner
        |
        +--> bitcoin-node-health
        |
        +--> bitcoin-node-telegram-alert
                 |
                 v
              Telegram


macOS LaunchAgent
        |
        v
bitcoin-node-health-notify
        |
        v
Multipass health check
        |
        v
macOS Notification Center
```

## Telegram credentials

Create a bot by messaging the official verified `@BotFather` account and using:

```text
/newbot
```

Treat the bot token like a password. Never store it in Git, documentation, screenshots, shell history or chat messages.

The credentials are stored only inside the VM:

```text
/etc/bitcoin-node-health/telegram.env
```

Create the protected directory:

```bash
multipass exec bitcoin-node -- \
  sudo install -d -o root -g root -m 0700 \
  /etc/bitcoin-node-health
```

Create the credentials file:

```bash
multipass exec bitcoin-node -- \
  sudo nano /etc/bitcoin-node-health/telegram.env
```

Its format is:

```bash
TELEGRAM_BOT_TOKEN='REPLACE_WITH_REAL_TOKEN'
TELEGRAM_CHAT_ID='REPLACE_WITH_NUMERIC_CHAT_ID'
```

Secure it:

```bash
multipass exec bitcoin-node -- \
  sudo chown root:root /etc/bitcoin-node-health/telegram.env

multipass exec bitcoin-node -- \
  sudo chmod 600 /etc/bitcoin-node-health/telegram.env
```

Expected permissions:

```text
-rw------- 1 root root
```

The real token and chat ID must never be committed to this repository.

## Install the Telegram alert scripts

Transfer the runner:

```bash
multipass transfer \
  scripts/bitcoin-node-health-runner.sh \
  bitcoin-node:/tmp/bitcoin-node-health-runner.sh
```

Transfer the dispatcher:

```bash
multipass transfer \
  scripts/bitcoin-node-telegram-alert.sh \
  bitcoin-node:/tmp/bitcoin-node-telegram-alert.sh
```

Install both:

```bash
multipass exec bitcoin-node -- \
  sudo install -o root -g root -m 0755 \
    /tmp/bitcoin-node-health-runner.sh \
    /usr/local/bin/bitcoin-node-health-runner

multipass exec bitcoin-node -- \
  sudo install -o root -g root -m 0755 \
    /tmp/bitcoin-node-telegram-alert.sh \
    /usr/local/bin/bitcoin-node-telegram-alert
```

Install the updated systemd service:

```bash
multipass transfer \
  systemd/bitcoin-node-health.service \
  bitcoin-node:/tmp/bitcoin-node-health.service

multipass exec bitcoin-node -- \
  sudo install -o root -g root -m 0644 \
    /tmp/bitcoin-node-health.service \
    /etc/systemd/system/bitcoin-node-health.service

multipass exec bitcoin-node -- \
  sudo systemctl daemon-reload
```

Restart the timer:

```bash
multipass exec bitcoin-node -- \
  sudo systemctl restart bitcoin-node-health.timer
```

## Test Telegram delivery

The dispatcher includes a test mode that does not alter its saved state:

```bash
multipass exec bitcoin-node -- \
  sudo bash -c \
  'set -a; . /etc/bitcoin-node-health/telegram.env; /usr/local/bin/bitcoin-node-telegram-alert --test WARNING'
```

Read alert-related journal entries:

```bash
multipass exec bitcoin-node -- \
  journalctl -u bitcoin-node-health.service \
    --since "30 minutes ago" \
    --no-pager |
grep -E '\[(ALERT|ALERT-ERROR)\]'
```

The persistent Telegram alert state is stored at:

```text
/var/lib/bitcoin-node-health/last-state
```

## Install the macOS notification script

Install the script on the Mac:

```bash
sudo install \
  -o root \
  -g wheel \
  -m 0755 \
  scripts/macos-bitcoin-node-notify.sh \
  /usr/local/bin/bitcoin-node-health-notify
```

Test Notification Center:

```bash
/usr/local/bin/bitcoin-node-health-notify --test
```

The host-side state is stored at:

```text
~/Library/Application Support/bitcoin-node-guide/macos-last-state
```

The host-side log is stored at:

```text
~/Library/Logs/bitcoin-node-health-notify.log
```

## Install the macOS LaunchAgent

Install its property list:

```bash
mkdir -p "$HOME/Library/LaunchAgents"

install -m 0644 \
  launchd/com.pzhendov.bitcoin-node-health-notify.plist \
  "$HOME/Library/LaunchAgents/com.pzhendov.bitcoin-node-health-notify.plist"
```

Validate it:

```bash
plutil -lint \
  "$HOME/Library/LaunchAgents/com.pzhendov.bitcoin-node-health-notify.plist"
```

Load it:

```bash
launchctl bootstrap \
  "gui/$(id -u)" \
  "$HOME/Library/LaunchAgents/com.pzhendov.bitcoin-node-health-notify.plist"
```

Enable and trigger it:

```bash
launchctl enable \
  "gui/$(id -u)/com.pzhendov.bitcoin-node-health-notify"

launchctl kickstart -k \
  "gui/$(id -u)/com.pzhendov.bitcoin-node-health-notify"
```

The LaunchAgent runs once when loaded and every five minutes afterward.

A one-shot LaunchAgent normally reports:

```text
state = not running
last exit code = 0
```

between scheduled executions.

## Local Network permission

macOS may ask whether Multipass can find devices on local networks. This permission is required for the LaunchAgent to communicate with the local Bitcoin VM.

The permission can be reviewed or revoked under:

```text
System Settings
→ Privacy & Security
→ Local Network
→ Multipass
```

## View macOS monitoring results

```bash
tail -n 20 \
  "$HOME/Library/Logs/bitcoin-node-health-notify.log"
```

A normal unchanged check looks like:

```text
Check completed: state=HEALTHY previous=HEALTHY
State unchanged; no macOS notification displayed
```

If Multipass fails to return a valid health summary, the script waits ten seconds and retries before declaring a critical state. This reduces false alerts during VM startup, Mac wake-up and temporary networking changes.

## Unload the LaunchAgent

The following commands are for future maintenance. Do not run them while macOS monitoring should remain active.

Unload it:

```bash
launchctl bootout \
  "gui/$(id -u)" \
  "$HOME/Library/LaunchAgents/com.pzhendov.bitcoin-node-health-notify.plist"
```

Disable it:

```bash
launchctl disable \
  "gui/$(id -u)/com.pzhendov.bitcoin-node-health-notify"
```

## Security notes

- Never commit `telegram.env`.
- Never paste the bot token into an issue, pull request or chat.
- Revoke and replace the token through BotFather if it is exposed.
- Keep the credentials directory mode `0700`.
- Keep the credentials file mode `0600`.
- Alerts contain operational status only.
- The alert scripts do not have access to wallet private keys.
- The Bitcoin Core wallet remains disabled in this node configuration.
